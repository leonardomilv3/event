# 2026-10-15

## Contexto

Configuração de `docs/` como vault do Obsidian. O objetivo é organizar o conhecimento e o histórico do Eventing em notas que Obsidian, GitHub e Claude Code leiam do mesmo jeito. Na auditoria inicial: nenhum `.md` de `docs/` tinha frontmatter, os 13 ADRs declaravam `Accepted`, havia 0 links relativos quebrados em `docs/` e no README, e nenhuma credencial real em `docs/`, `notes.md` ou na raiz. Os únicos `.md` soltos na raiz são `notes.md`, `README.md` e `CLAUDE.md`; os `EVENTING_*.md`, `PLAN.md` e `IMPLEMENTATION_PLAN.md` citados no pedido não existem no repositório.

## Decisões

- **Links Markdown relativos, nunca wikilinks**: o GitHub não renderiza `[[...]]`. O Obsidian foi configurado para gerar links relativos (`.obsidian/app.json`).
- **Só três arquivos de `.obsidian/` versionados** (`app.json`, `templates.json`, `daily-notes.json`): workspace, cache e plugins são estado local de cada máquina.
- **`!scripts/check-vault.sh` no `.gitignore`**: o padrão `*.sh` já existente ignoraria o script.
- **Frontmatter só no topo dos documentos existentes**: o corpo dos ADRs não foi alterado, e `date` vem do primeiro commit de cada arquivo.
- **Detector de segredos do script procura atribuição de valor** (`password=`/`senha:`), não a palavra solta. Senão `components.md` (que descreve `PasswordInput`) falharia sempre.
- **Postmortems ficam em `runbooks/`** até existir o primeiro; se ganham pasta própria está a definir.
- **Situação na priorização só com evidência**. Exemplos: participação em `PUBLIC` foi removida só no front (commit 8ccb818) e a API não bloqueia join; upload de banner não existe (só a coluna `cover_image_url`).
- **Comando `/log-session` em `.claude/commands/`** com `allowed-tools` limitado a leitura de git, `date`, o script de verificação e escrita em `docs/`.

## Mudanças

- Estrutura do vault: `product/`, `runbooks/`, `experiments/`, `prompts/`, `journal/` e `_templates/`, com seis templates (adr, experiment, prompt, journal, runbook, postmortem).
- Notas novas: [index.md](../index.md), [vault-guide.md](../vault-guide.md), [priorizacao.md](../product/priorizacao.md), [funil-compartilhamento.md](../experiments/funil-compartilhamento.md) (baseado no [ADR-012](../adrs/012-posthog-funnel-analytics.md)).
- Frontmatter em 20 documentos existentes: 120 linhas adicionadas, 0 removidas.
- Seção "Vault de conhecimento" no `CLAUDE.md` (importa `@docs/index.md`); seções acrescentadas ao `documentation-agent` e ao `architecture-agent`.
- `scripts/check-vault.sh` verifica frontmatter, wikilinks, links quebrados, segredos e ADR duplicado. Foi testado com casos negativos e passa no vault (30 notas). README ganhou um parágrafo sobre o vault.
